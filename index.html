⬡01 / CAPTURE

Packets analyzed

A packet is one small unit of network data. This number counts all packets in the capture file, including those unrelated to the selected IoT device.

How the analyzer calculates itThe browser reads the capture file locally and counts its packet records.
More packets means more observed traffic, not automatically more danger.
⚑02 / SECURITY

Security alerts

The number of findings generated by three rules: unusual destination ports, connections on potentially unsafe protocol ports, and HTTP request bursts.

How the analyzer calculates itEach rule-generated finding is counted, not each attack or malicious packet. The frontend assigns High / Medium display labels.
Alerts are clues for investigation, not proof a device was hacked. See actual findings →
⇄03 / WEB TRAFFIC

HTTP requests

Counts outgoing TCP packets from the selected device whose visible payload starts with GET or POST.

How the analyzer calculates itIt inspects TCP packet payloads for the literal beginnings GET or POST .
It does not count every web request, and it cannot read encrypted HTTPS content.
◷04 / TIMING

Capture duration

The span of time between the first and last packet timestamps in the file, shown in seconds.

How the analyzer calculates itTime of last packet minus time of first packet, rounded to one decimal.
This is the observation window, not how long the device has been running.
▥05 / PROTOCOLS

Protocol breakdown

Groups observed IPv4 packets into DNS, TCP, UDP, or Other. DNS is checked first, so those packets are counted as DNS rather than also as TCP or UDP.

How the analyzer calculates itEvery supported IPv4 packet goes into one category based on its headers and ports.
Bars show packet counts by category, not percentages of bandwidth. Explore protocol data →
⌗06 / PORTS

Top destination ports

Shows which destination service ports the chosen device sent traffic to most often. For example, port 80 is commonly HTTP and 443 is commonly HTTPS.

How the analyzer calculates itCounts TCP and UDP destination port values for outgoing IPv4 packets from the chosen IP.
A port number alone cannot prove which application or encryption a connection used.
◎07 / DEVICE

Most active source IP

The analyzer chooses the IPv4 address that sent the most packets in the file. It then treats that address as the IoT device for outbound traffic statistics and alert checks.

How the analyzer calculates itCounts each IPv4 source address and selects the most frequent one.
If a different device talks more than your ESP32, it may select the wrong IP.
⇢08 / CONNECTIONS

Connection attempts

Counts outgoing TCP packets that have the SYN flag set without ACK. These often mark the beginning of a TCP handshake.

How the analyzer calculates itOne count for each outgoing SYN-only packet from the selected device.
Retries can increase this count. It does not tell you if connections succeeded.
⌁09 / ADDRESSES

Destination addresses

The unique destination IPv4 addresses the selected device sent packets to. The traffic page shows how many outgoing packets went to each address.

How the analyzer calculates itCounts the destination IP on outgoing IPv4 packets from the selected source IP.
It is a count of observed addresses, not necessarily devices on your home network.
